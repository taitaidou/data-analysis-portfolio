# PRD：用户分层与召回运营工作台 V0.1

状态：个人产品设计与模拟原型。面向运营人员的假设场景，尚未做真实访谈或产品上线。

## 1. 问题与目标
原游戏分析提供活跃、留存和分层结果，但尚不能让运营人员完成“选人—定策略—审核—复盘”。假设运营人员存在重复请求取数、分层口径不统一和缺少复盘记录的问题。需访谈验证，而非已证实业务痛点。

目标：设计可追溯、可解释的召回任务流程。业务效果需实验验证，未设置没有依据的提升承诺。
目标用户：运营专员创建任务；运营负责人审核；分析人员定义指标；研发/算法提供数据及模型能力。后两者是拟议分工，不代表已经开展跨团队合作。

## 2. 范围与优先级
P0：规则人群、预览快照、任务配置、人工审核、模拟执行、结果口径。
P1：AI辅助文案、失败重试设计、实验配置。
不纳入V0.1：在线大模型服务、内容推荐算法、真实推送、预算计费、渠道集成、跨租户权限。原型用模板和固定实验数据演示P1概念。

## 3. 数据定义
分析日期为D，时区UTC，所有行为只读至D结束；生产数据到齐后才能计算。首次出现不代表注册，历史不足时不推断真实资历。

| 字段 | 定义 |
| --- | --- |
| user_id | 内部去标识化标识，不在原型使用真实用户 |
| first_seen | 当前可观察历史中首次有效活跃日期 |
| last_active | 截至D最近有效活跃日期 |
| active_days | 截至D累计去重活跃日期数 |
| consent | 渠道授权状态；未知视为不可触达 |
| last_touch | 最近成功触达时间，用于频控；真实数据需渠道补齐 |
| snapshot_id | 规则、数据版本、分析日期和候选ID集合的不可变版本 |

拟议规则：D-first_seen≥14天、active_days≥3、D-last_active≥7天、授权为允许，且过去7天无成功触达。阈值是设计默认值，不是已验证最优策略。有效活跃事件集需埋点字典确认，排除系统后台事件。
原型100个虚构用户固定在D=2026-10-01；无法选择其他日期。模拟规则提供未活跃阈值、历史活跃天数，其他条件固定。人数计算完成才能提交任务。条件变化立即使预览与审核失效。

## 4. 页面与主流程
人群管理：输入规则→预览人数/生成快照→进入策略配置。
策略配置：任务名、App Push渠道、活动事实、文案、未来计划时间→校验→待审核。
审核与执行：查看快照人数、完整文案、时间→审核通过或驳回→模拟执行/取消。
效果复盘：演示固定实验数据与指标，明确不来自当前任务。

状态：草稿→待审核→待执行→已完成；待审核可驳回，未完成任务可取消。原型执行为即时模拟，忽略计划时间但明确说明；真实系统到计划时间才进入执行中，最终记录成功/部分失败/失败。
修改任务配置或人群规则后回到草稿，清除原审核和任务快照；重新预览并提交后产生新任务版本。已执行记录应在生产系统保留，不得覆盖。原型只保留本次内存演示，不提供审计持久化。

## 5. 功能与异常
F01 预览：条件为非负整数，活跃天数至少1；非法值、空人群均禁止提交。
F02 配置：任务名/文案/时间必填，文案≤80个字符，渠道固定App Push；时间晚于设备当前时间。生产环境使用服务端时间和明确时区。
F03 文案：允许活动事实仅为“欢迎回到游戏，查看最新关卡”；模板不得出现未提供的奖励。原型只演示禁用词检查，不能替代真正的事实与政策审核。
F04 审核：原型角色切换展示运营和审核职责；这不是安全权限系统。真实系统需服务端鉴权及创建人与审核人不同。
F05 防重：同一任务版本执行一次后禁止重复执行。真实系统以任务版本+用户+渠道作为幂等键，并在发送前再次检查授权、频控和用户是否已回访；不应扩充已审核人群，只允许排除不再符合的人。
F06 失败：生产渠道失败按可重试/永久失败区分，重试不重复成功记录；取消后停止未发送部分，保留已发送事实。原型无实际渠道，全部模拟成功。

## 6. AI辅助设计
输入结构：已批准活动事实、群体描述、文案长度与语气；禁止传入敏感个人明细。输出三个候选文案与引用事实。运营选取/编辑后仍需审核。
原型按钮只返回三个固定模板，无模型调用。后续接入时评估事实支持率、禁用内容率、人工采用率和编辑耗时；规则分层不是大模型分层。模型超时/无合格输出则退回人工编辑。

## 7. 验收标准
AC01 改变规则后旧预览清空、旧审核失效。
AC02 无预览、人数为0、非法条件、缺字段或过去时间均不能提交。
AC03 运营身份不能审批；审核身份不能代运营提交（原型仅演示）。
AC04 修改审核后的文案必须重新预览、提交、审核。
AC05 未审批不能执行；同版本不可重复执行。
AC06 取消的任务不可执行，修改后需新版本提交。
AC07 效果页面显著标明模拟结果，不能把固定结果解释为本次发送收益。
AC08 页面可键盘操作，移动端不遮挡主要按钮，表单错误以文本反馈。

## 8. 上线前待验证
访谈运营：当前选人耗时、召回任务频率、审批权责、失败处理成本。核对有效活跃定义、用户级特征准确性与数据延迟。确认渠道授权与退订机制；实施后台权限、日志和发送幂等性；完成小流量验收后再设计正式实验。见指标文档。
