# 指标、埋点与实验设计

以下为拟议方案，没有真实运营效果。原型结果固定模拟，不能更新原游戏分析结论。

## 指标口径
| 指标 | 分子 / 分母或计算 | 用途 |
| --- | --- | --- |
| 任务配置耗时 | 成功提交时间-首次开始配置时间；排除取消任务单列 | 操作效率，报告中位数和P90 |
| 送达率 | 去重成功送达人数/去重尝试触达人数 | 渠道质量；重试不增加去重人数 |
| 7天回访率 | 分组时点后(0,168小时]内至少一次有效活跃的用户数/该组全部随机分配人数 | 主指标，ITT口径，不剔除未送达用户 |
| 效果差 | 实验组回访率-对照组回访率，单位百分点 | 与相对提升分开 |
| 退订率 | 窗口内退订人数/该组随机分配人数 | 两组可比护栏；需相同日志覆盖 |
| 投诉率 | 窗口内投诉人数/该组随机分配人数 | 护栏；零投诉不代表绝对安全 |
| 人均触达次数 | 成功触达次数/去重成功触达人数 | 频次分布同时报告 |

送达人数不适合作为实验组与不发送对照组的共同分母。按组分配人数报告主要结果；发送后的回访不能自动归因于消息。

## 实验方案
入组前冻结规则、观察日期、可触达条件；明确过去活动的排除期。候选用户按稳定用户ID随机1:1分组，保留分流记录；对照组不接受本次召回，但其他运营需尽量一致或明确记录。处理跨设备重复、跨任务重叠和同期活动污染。
预先指定7天回访为主指标；未观察满168小时者暂不出最终结果，数据水位达到窗口末尾后统一分析。确定基线、最小有意义绝对差MDE、显著性水平与统计功效后计算样本量；没有这些信息不承诺样本量或显著性。
先检查分流比例异常（SRM）、数据缺失和事件覆盖，再报告两组人数、回访率、绝对差及置信区间。无固定方案时不反复查看显著性并提前停止；提前停止规则须预注册。次级指标和分组分析标为探索性，并考虑多重比较。

模拟示例：实验组100人、回访18人；对照组100人、回访12人；差6个百分点。仅为算术演示，不证明统计显著、因果效果或业务收益。

## 埋点契约
公共字段：event_id、event_time_utc、actor_id、role、task_id、task_version、snapshot_id、schema_version。用户级发送记录仅在授权受控环境保存，不上传公开仓库。

| 事件 | 触发点 | 关键字段 |
| --- | --- | --- |
| audience_previewed | 后端完成快照计算 | rule_version,data_watermark,eligible_count |
| task_submitted | 校验通过并保存 | channel,scheduled_time,content_version |
| task_reviewed | 审批结果落库 | decision,reason,reviewer_id |
| user_assigned | 实验分组落库 | experiment_id,group,pseudonymous_user_id,assignment_time |
| delivery_attempted | 开始发送 | idempotency_key,attempt_no |
| delivery_confirmed | 渠道明确回执 | provider_event_id,status,error_code |
| user_active | 合法前台活跃 | user_id,event_name,source |
| user_opted_out | 用户取消授权 | channel,effective_time |

回执按渠道事件ID去重；事件时间与接收时间分开存储，延迟事件按水位补算。后续建立用户ID、任务版本、随机组、活跃事件的关联质量检查。浏览器原型不产生上述生产埋点。
