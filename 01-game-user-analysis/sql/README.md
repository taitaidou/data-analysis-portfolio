# 游戏项目 SQL

本目录保存项目提供的七份原始查询，使用 BigQuery GoogleSQL，数据表为 `firebase-public-project.analytics_153293282.events_*`。本次仅整理上传，未修改 SQL，也未连接 BigQuery 执行验证。

| 文件 | 内容 |
| --- | --- |
| `探索性分析.sql` | 事件分布、数据日期范围及明细样例；包含三个独立查询 |
| `dau.sql` | 每日活跃用户数、事件数与人均事件数 |
| `rolling wau.sql` | 当日及前六日的去重活跃用户数 |
| `D1andD7 留存分析.sql` | 按数据范围内首次出现日期构建 Cohort，计算 D1/D7 留存 |
| `版本表现分析.sql` | 版本覆盖人数、事件数、人均事件数及完成关卡人数 |
| `分群(设备，国家，活跃频次).sql` | 当前实际内容仅为设备分群 |
| `关键行为漏斗分析及转化率.sql` | 各关键事件的去重用户数及人数比值；包含两个独立查询 |

## 使用说明

在有权查询公开数据集的 BigQuery 环境中运行。包含多个查询的文件可分段执行并分别导出结果。代码目前未限定表后缀日期范围，执行前应确认扫描范围与预计处理量。

## 当前指标边界

- 留存以数据范围内首次出现日期定义 Cohort，不等同于已核实的真实新用户；尚未排除观察期不足一天或七天的 Cohort，相关口径需完善后重新导出结果。
- 当前漏斗查询未使用时间戳，也未限制同一批用户按顺序完成事件，因此输出属于事件覆盖人数及比值，不能解释为严格时序漏斗转化率。
- 分群文件名包含国家和活跃频次，但实际 SQL 尚未覆盖这两部分。
- 同一用户可出现在多个版本或设备分组，分组用户数不应直接相加作为总用户数。
- 原始查询本身不能验证简历中的结果数字，需结合实际结果表复核。
