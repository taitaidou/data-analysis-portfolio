## 环境与执行说明

- 分析脚本使用 `orders`、`returns`、`people` 表；部分语句显式引用 `retail_analysis` 数据库。
- CTE 与窗口函数需要 MySQL 8.0 或兼容环境。原始数据、建表导入脚本及字段字典尚未提供。
- 这些文件是分阶段分析脚本，不是可直接全部重复执行的安装脚本。应先确认表结构与字段类型，再逐段运行。
- `02_data_cleaning.sql` 用于原始字符串日期检查；`021_data_cleaning.sql` 会新增、更新、删除并重命名列。日期已转换后，不应直接重复执行该结构变更文件。转换和检查完成后再执行依赖日期的趋势与日期比较查询。
- `08_returns_analysis.sql` 会创建 `returns_clean` 表和 `returns_view` 视图，重复运行可能因对象已存在而失败。代码中的原始 `Order ID` 列名前包含不可见字符，需与实际导入列名匹配。
- 多数文件包含多个独立语句，结果应按查询分别导出。

## 指标口径

- `profit_margin` = 总利润 / 总销售额 × 100；`total_orders` 和 `total_customers` 分别按订单 ID 和客户 ID 去重。
- `avg_order_value` = 总销售额 / 去重订单数；`record_count` 表示记录行数，不等同于去重订单数。
- `return_rate` = 关联到退货表的去重订单数 / 订单表去重订单数 × 100。代码未筛选 `Returned` 标记，需确认退货源表是否仅含已退货订单；跨品类订单可能进入多个品类分母，分类计数不可直接相加。
- 退货订单对应的销售额与利润不等同于净退款金额或实际退货损失；关联前需检查退货表订单键唯一性，避免销售额与利润重复计算。
- `regional_manager` 关联需确认 `people.region` 唯一性，避免一对多关联放大金额。
- `profit_margin`、`return_rate`、同比／环比、折扣均值等百分数字段在相关查询中已乘以 100；导入 Tableau 后应核对单位，避免再次放大。
- 折扣和利润差异为描述性比较，不能直接认定因果。月度环比使用上一条观测月份，需先确认月份是否连续。
